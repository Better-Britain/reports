# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Static HTML generated by a Node build script (`site/assets/microsites/billionaire-database/build.js` → `docs/billionaire-database/`), published under `/billionaire-database/` inside the Better Britain Bureau report site. No framework, no runtime JS dependency — content must work with JavaScript off.

## Users

Curious readers who want to understand how billionaire power connects — who runs with whom, which fortunes are one family wearing many names, who the brokers are. They read it like an article, mostly on whatever device they have. Secondary (the site owner): a research loop that packages unanswered questions as downloadable briefs.

## Product Purpose

An explorer of the billionaire web: 3,394 people, ~610 with evidenced ties, built from a Forbes snapshot + curated research + feed assertions. The point is the relationships — dynasties, founding pairs, brokers, cross-web reach — not the dataset mechanics. Success = a reader leaves able to say *who* holds power *together* and how.

## Positioning

Person-first: every connected person has a page answering "who they run with"; names are the links; prose carries claims; data quality is a footnote at the bottom of the page, not decoration. No other rich-list site presents the relational structure rather than the ranking.

## Capabilities and Constraints

- All content baked at build time; SVG graphs are build-time layouts, links are real anchors.
- Must work on mobile — no single giant page; substantial webs get their own pages, pairs/triads are directory lines.
- Tier discipline: sourced (researched), feed-labeled (unverified), context (shared assets) must stay distinguishable.
- No invented content: every claim comes from `relationships` labels/summaries or the roster; gaps are stated as gaps.
- Never commit to git — the user commits.

## Brand Commitments

Part of Better Britain Bureau reporting. Data quality/provenance stays on every page as small print. The word "honest" is banned everywhere.

## Evidence on Hand

`site/assets/microsites/billionaire-database/data/` — people/relationships/entities JSONL, ~2.7MB, snapshot 17 Nov 2026. Research briefs under `gaps/`. Prior user verdict: the current look reads as dated and database-flavoured; a full visual + structural redesign is approved.

## Product Principles

1. Every number becomes a name — stats are about people and money, never records.
2. Names are the links — never a separate "their web" label.
3. Prose is the structure, not the filler between widgets.
4. Data quality is a literal footnote.
5. The reader's question is "who does X run with" — everything answers that first.
